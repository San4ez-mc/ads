# АПІ сайтів для платформи реклами — що потрібно доробити на хостингу

> Для власника (робить сам на хостингу). Складено 16.11.2026.
> Мета: платформа реклами має бачити кроки людини на сайті (зайшов → натиснув → заповнив форму → оплатив)
> у розрізі **оголошення**, з якого людина прийшла, і вміти з'єднати сайт із ботом та оплатою.

Є дві частини: **А** — що сайт має запам'ятовувати і передавати далі (без цього АПІ нема чого віддавати),
**Б** — самі методи АПІ.

---

## А. Що сайт має робити сам

### А1. Запам'ятати, звідки прийшла людина

У кожному рекламному посиланні платформа реклами сама дописує параметри (Meta підставляє значення):

```
https://auto-lp.fineko.space/?utm_source=meta&utm_medium=paid
  &campaign_id={{campaign.id}}&adset_id={{adset.id}}&ad_id={{ad.id}}
  &placement={{placement}}&utm_campaign=...&utm_content=...
```

При першому заході сайт:

1. читає з адреси: `utm_source, utm_medium, utm_campaign, utm_content, utm_term, campaign_id, adset_id, ad_id, placement, fbclid, gclid`;
2. створює **`visitor_id`** (випадковий рядок, кука на 90 днів) — та сама людина при повторних заходах;
3. створює **`click_id`** — короткий код цього заходу: **10 символів, лише `a-z A-Z 0-9`** (його треба буде вкласти в посилання на Telegram, там жорсткий ліміт довжини й набору символів);
4. зберігає в базі рядок «захід»: `click_id, visitor_id, час, усі параметри з п.1, адреса сторінки, звідки прийшов (referrer), варіант сторінки, пристрій (mobile/desktop)`.

Якщо людина прийшла вдруге вже без параметрів — джерело **першого** заходу не затирати (зберігати і перше, і останнє).

### А2. Писати подію на кожному кроці

Кожна подія прив'язана до `visitor_id` і `click_id`. Мінімальний набір ключів кроків (однакові на всіх сайтах):

| Ключ | Коли |
|---|---|
| `view` | відкрив сторінку |
| `cta_click` | натиснув головну кнопку |
| `tg_click` | натиснув перехід у Telegram |
| `form_open` | відкрив форму |
| `form_submit` | відправив форму (заявка) |
| `booking` | записався на час (календар) |
| `pay_start` | перейшов до оплати |
| `pay_success` | оплата пройшла (із сумою) |
| `pay_fail` | оплата не пройшла |
| `refund` | повернення (із сумою) |

Свої додаткові ключі дозволені (наприклад `scroll_50`, `video_play`) — головне, щоб вони були в переліку кроків (метод Б2).
`pay_success` і `refund` писати **з сервера** за відповіддю платіжної системи, а не з браузера.

### А3. Передати код далі

- **Кнопка «в Telegram»:** `https://t.me/<бот>?start=<воронка>__c<click_id>`
  приклад: `https://t.me/den_fineko_bot?start=bot-karta-sales__cA7kP2mQx9Z`.
  Разом не більше 64 символів, лише літери, цифри, `_` і `-`. Flows запише цей код у розмову — так бот «дізнається» оголошення.
- **Оплата на сайті:** `click_id` класти в призначення/посилання замовлення платіжної системи, щоб при відповіді про оплату подія `pay_success` отримала той самий `click_id`.
- **Запис у календар:** у посилання `calendar.fineko.space/book/...` додавати `&s=c<click_id>` (поле «джерело» там уже є).
- **Заявка в Hub (leads.fineko.space):** разом із заявкою передавати `click_id`.

### А4. Варіанти сторінки

Якщо для однієї адреси є кілька варіантів (інший заголовок, інша ціна) — у кожній події писати `variant` (короткий ключ: `a`, `b`, `price1500`). Так платформа порівняє варіанти лендінгу між собою.

### А5. Лічильник Meta (піксель)

Поставити на лендінги піксель Meta зі стандартними подіями: `PageView`, `Lead` (на `form_submit` і `tg_click`), `InitiateCheckout` (на `pay_start`), `Purchase` (на `pay_success`, із сумою і валютою). У кожну подію передавати `eventID` = id нашої події (щоб потім не було подвійного рахунку, коли додамо відправку з сервера). Без пікселя Meta не знає, хто купив, і не може шукати схожих людей — реклама виходить дорожчою.

## Б. Методи АПІ

Загальне:

- Базова адреса одна на всі сайти, наприклад `https://leads.fineko.space/api/ads/v1` (якщо зручніше — окремо на кожному сайті, тоді ключ на сайт).
- Вхід: заголовок `Authorization: Bearer <ключ>`. Ключ лише на читання; створюється в адмінці, можна відкликати.
- Формат: JSON, UTF-8. Час — ISO 8601 в UTC (`2026-11-16T09:30:00Z`). Гроші — число + `currency` (`UAH`).
- Успіх: `{ "ok": true, "data": ... }`. Помилка: `{ "ok": false, "error": { "code": "...", "message": "..." } }` з кодом 401 (ключ), 400 (параметри), 429 (забагато запитів), 500.
- **Без особистих даних:** імена, телефони, пошту не віддавати. Досить `lead_id` (номер заявки в Hub).
- Тестові заходи (ваші власні, з параметром `test=1` або з вашої IP) позначати `is_test: true`.

### Б1. `GET /ping` — перевірка ключа

Потрібен для кнопки «Перевірити підключення» на платформі.

```json
{ "ok": true, "data": { "service": "fineko-sites", "version": "1", "time": "2026-11-16T09:30:00Z" } }
```

### Б2. `GET /sites` — перелік сайтів і їх кроків

З цього платформа сама малює сайт на карті як послідовність кроків, включно з розгалуженнями.

```json
{ "ok": true, "data": { "sites": [
  {
    "id": "auto-lp",
    "domain": "auto-lp.fineko.space",
    "name": "Розбір процесу — консультація",
    "variants": ["a"],
    "steps": [
      { "key": "view",        "title": "Відкрив сторінку", "order": 1 },
      { "key": "cta_click",   "title": "Натиснув кнопку",  "order": 2 },
      { "key": "tg_click",    "title": "Перейшов у Telegram", "order": 3, "branch": "telegram", "leads_to": "flows:bot-karta-sales" },
      { "key": "pay_start",   "title": "Почав оплату",     "order": 3, "branch": "pay" },
      { "key": "pay_success", "title": "Оплатив",          "order": 4, "branch": "pay", "is_sale": true }
    ]
  }
] } }
```

Поля кроку: `key`, `title`, `order` (однаковий `order` + різний `branch` = розгалуження), `branch` (необов'язково),
`leads_to` (куди веде далі: `flows:<slug воронки>`, `calendar:<slug>`, `site:<id>`; необов'язково), `is_sale` (цей крок = продаж; платформа враховує його лише для `pay_success`: заявка чи завантаження клієнтом не є).

### Б3. `GET /events` — стрічка подій (головний метод)

Платформа забирає нові події раз на годину (через воронку Flows) і все рахує сама.

Параметри:

| Параметр | Обов'язковий | Опис |
|---|---|---|
| `after_id` | так (перший раз `0`) | віддати події з `id` більшим за це число |
| `limit` | ні | скільки за раз, за замовчуванням 1000, максимум 5000 |
| `site` | ні | лише один сайт |

Події віддавати за зростанням `id`. `id` — ціле число, що лише росте (звичайний автоінкремент таблиці подій).

```json
{ "ok": true, "data": {
  "events": [
    {
      "id": 48211,
      "ts": "2026-11-16T09:12:44Z",
      "site": "auto-lp",
      "step": "view",
      "variant": "a",
      "visitor_id": "v_8f3a1c9d2e",
      "click_id": "A7kP2mQx9Z",
      "is_test": false,
      "device": "mobile",
      "source": {
        "utm_source": "meta", "utm_medium": "paid",
        "utm_campaign": "consult-nov", "utm_content": "pain-routine-1", "utm_term": null,
        "campaign_id": "120250000000000001", "adset_id": "120250000000000002", "ad_id": "120250000000000003",
        "placement": "Instagram_Reels", "fbclid": "IwAR...", "gclid": null,
        "referrer": "https://l.instagram.com/", "landing_url": "https://auto-lp.fineko.space/"
      },
      "first_source": { "ad_id": "120250000000000003", "utm_source": "meta", "ts": "2026-11-16T09:12:44Z" },
      "amount": null, "currency": null,
      "order_id": null, "lead_id": null, "product": null
    },
    {
      "id": 48260,
      "ts": "2026-11-16T09:19:02Z",
      "site": "auto-lp", "step": "pay_success", "variant": "a",
      "visitor_id": "v_8f3a1c9d2e", "click_id": "A7kP2mQx9Z", "is_test": false, "device": "mobile",
      "source": { "ad_id": "120250000000000003", "adset_id": "120250000000000002", "campaign_id": "120250000000000001", "utm_source": "meta" },
      "first_source": { "ad_id": "120250000000000003", "utm_source": "meta", "ts": "2026-11-16T09:12:44Z" },
      "amount": 1500, "currency": "UAH",
      "order_id": "WFP-2026-000431", "lead_id": 915, "product": "rozbir-procesu"
    }
  ],
  "last_id": 48260,
  "has_more": false

```

Пояснення полів:

- `source` — джерело **цього** заходу (усі параметри з А1; чого нема — `null`). У подіях після `view` можна віддавати скорочено, але `ad_id` — завжди, якщо він відомий.
- `first_source` — джерело найпершого заходу цієї людини (`visitor_id`).
- `amount`, `currency`, `order_id` — лише для `pay_start`, `pay_success`, `pay_fail`, `refund`.
- `lead_id` — номер заявки в Hub, якщо подія її створила або стосується.
- `product` — ключ продукту, якщо на сайті їх кілька.

Подія, записана заднім числом (оплата підтвердилась через годину), отримує **новий більший `id`** і свій справжній `ts` — тоді платформа нічого не пропустить.

### Б4. `GET /clicks/{click_id}` — джерело за кодом

Потрібен, коли бот або менеджер має лише код, а платформі треба оголошення.

```json
{ "ok": true, "data": {
  "click_id": "A7kP2mQx9Z", "visitor_id": "v_8f3a1c9d2e", "site": "auto-lp", "variant": "a",
  "ts": "2026-11-16T09:12:44Z", "is_test": false,
  "source": { "campaign_id": "…", "adset_id": "…", "ad_id": "…", "utm_source": "meta", "utm_content": "pain-routine-1", "placement": "Instagram_Reels" }
} }
```

Невідомий код → 404 з `error.code = "not_found"`.

### Б5. `GET /summary` — зведення (бажано, не обов'язково)

Для звірки: платформа порівнює свої підрахунки з вашими і б'є тривогу, якщо розходяться.

Параметри: `from`, `to` (дати `YYYY-MM-DD`, за київським часом, включно), `site` (необов'язково), `group_by` = `day` | `ad_id` | `variant`.

```json
{ "ok": true, "data": { "rows": [
  { "group": "120250000000000003", "site": "auto-lp",
    "steps": { "view": 412, "cta_click": 96, "tg_click": 61, "pay_start": 9, "pay_success": 4 },
    "revenue": 6000, "currency": "UAH" }
] } }
```

У `steps` — кількість **унікальних людей** (`visitor_id`), що зробили крок за період, без тестових.

### Б6. Миттєве сповіщення про оплату (бажано)

Щоб оплата з'являлась на платформі одразу, а не через годину: при `pay_success` і `refund` сайт сам надсилає
`POST` на адресу, яку дам пізніше (`https://ads.fineko.space/api/hooks/site-event`), з тілом = одна подія у форматі Б3
і заголовком `X-Signature` = HMAC-SHA256 тіла спільним секретом. Якщо не вийшло доставити — нічого страшного, подію підбере Б3.

## Порядок і перевірка

1. А1–А3 (запам'ятати джерело, події, код у посилання на Telegram) — без цього решта не має сенсу.
2. Б1, Б2, Б3 — мінімум, з яким платформа вже працює.
3. Б4, А4, А5.
4. Б5, Б6 — коли буде час.

Як перевірити самому: зайти на лендінг за посиланням із `?ad_id=TEST123&utm_source=meta&test=1`, пройти до оплати або
в Telegram, потім викликати `GET /events?after_id=0&site=auto-lp` — у всіх подіях має бути той самий `click_id`
і `ad_id = TEST123`, а в посиланні на бота — `__c<той самий код>`.
