# FINEKO Ads — правила роботи над проєктом

> Джерело правди: [`ПРОЄКТ-платформа-реклами.md`](./ПРОЄКТ-платформа-реклами.md). Розділ 0 (рішення власника) має перевагу над рештою.
> Контракт сайтів: [`АПІ-сайтів-для-платформи-реклами.md`](./АПІ-сайтів-для-платформи-реклами.md).

## 1. Що це

Платформа пошуку робочих рекламних зв'язок (аудиторія × обіцянка × шлях). Окремий сервіс: своя база `fineko_ads`,
порт 4900, домен `ads.fineko.space`, вхід через SSO (продукт `ads`). Стек і стиль — як у CRM і календарі
(Express + Prisma + React/Vite, npm workspaces `@ads/*`).

## 2. Запобіжники — не послаблювати

18 правил із розділу 5 проєкту. У коді вже діють:

- **Лише читання.** `apps/api/src/channels/meta.js` уміє тільки читати. Дії в кабінеті (увімкнути, вимкнути, бюджет,
  створити) додаються ОКРЕМИМ модулем, і кожна йде через одну точку перевірки запобіжників — не напряму з маршруту.
- **Ключі.** Шифруються `lib/secrets.js` (ключ `ADS_SECRET_KEY` лише в `.env`), назовні не віддаються ніколи
  (лише `…1234`). У Meta ключ іде в заголовку, не в адресі. Тексти помилок — через `scrub()`.
- **Ключ проєкту** (для воронок Flows) дає лише читання і запуск синхронізації: `lib/pageAccess.js → KEY_ALLOWED`.
- **Новий проєкт:** режим «проба» увімкнено, самостійність 0, денний ліміт 10 доларів. Підняти ліміт чи самостійність,
  вимкнути «пробу» — лише суперадмін.
- **Журнал:** кожна зміна — `services/journal.js → logAction`.
- **Обмеження частоти Meta:** не повторювати в циклі; одна синхронізація на проєкт за раз.

## 3. Правила коду

- Усі зміни — через git; на сервері файли не правити.
- Відповідь API завжди `{ ok: true, data }` або `{ ok: false, error: { code, message } }`.
- Звіти по багатьох оголошеннях — агрегованими запитами (`groupBy`), не запит у циклі.
- Колонка-дата (`InsightDaily.date`) порівнюється датами (`T00:00:00Z`), не моментами часу.
- Тексти інтерфейсу — простими словами, без жаргону; назви пунктів Meta — українською, в дужках англійською.
- Файли з кирилицею правити лише інструментами Edit/Write, не PowerShell.

## 4. Локальний запуск

```bash
npm install
npm run db:push            # база fineko_ads у локальному Postgres
node scripts/dev-setup.js  # клієнт ads у локальному SSO + тестовий користувач (.dev-user.json)
node scripts/dev-seed.js   # демо-проєкт із вигаданими даними (лише локально)
npm run dev:api            # :4900
npm run dev:admin          # :5175
npm test                   # наскрізна самоперевірка на локальній базі, без справжньої Meta
```

На цій машині порт 4600 зайнятий системою — локальний SSO піднімається на 4601 (`SSO_URL` у `.env`).

## 5. Стан

- Крок 1 (каркас, вхід, проєкти, підключення з майстром, синхронізація на читання, оголошення, журнал) — зроблено локально 16.11.2026.
- Крок 2, частина платформи: карта (`routes/map.js`, `admin/src/lib/mapLayout.js`, `pages/MapPage.jsx`) — зроблено локально 16.11.2026. Етапи ботів Flows на карті ще не видно: у Flows нема запису джерела в розмові й видачі етапів по оголошеннях.
- Дії в кабінеті (services/actions.js): вимкнути/увімкнути оголошення, бюджет групи; запобіжники 7–10, 13–18, режим «проба» за замовчуванням, підтвердження людини, перевірка після зміни. Перевірено лише на підробленій Meta — на справжній ще ні.
- Крок 6, створення кампаній (25.11.2026, локально): сторінка «Запуск», `services/launch.js` (єдина точка створення,
  запуску й зупинки), `routes/launches.js`, таблиця `launches`. Усе створюється вимкненим; мети: кліки, перегляди
  сторінки, ліди за піксельною подією; у посилання вписується справжній номер оголошення (другим креативом), а не
  макрос Meta. Тексти й картинки лише з контент-платформи, без правки в платформі реклами (інакше обхід перевірки
  правил). Перевірено на імітації Meta; на справжньому кабінеті ще ні. Можливі пастки: додаток Meta в режимі
  розробки (помилка 1885183), права ключа на Facebook-сторінку.
- `META_API_VERSION` має бути v26.0: старі версії (v21.0) Meta закрила.
- 26.11: справжній кабінет підключено. Карта одна («по зв'язках / по кампаніях»), з «Кому/Де», «Аналізувати»
  (`lib/analyze.js`) і «Внести правки» (`set_placements`, `replace_creative` у `services/actions.js`). «Історія»
  тестів (`routes/experiments.js`, `scripts/seed-history.js`). Audience Network і Threads у «Запуску» лише за галочкою.
- **Мета власника:** знайти робочу воронку продажу консультацій. План — [`ПЛАН-пошуку-воронки.md`](./ПЛАН-пошуку-воронки.md);
  кожен варіант заносити в «Історію» й не повторювати перевірене.
- Не зроблено: модуль Google, кнопки підтвердження в Telegram, автоправила рівнів 2–3, воронка-тривога щогодини,
  кнопка «Зупинити все» (запобіжник 12), ручне пересування карток на карті.
