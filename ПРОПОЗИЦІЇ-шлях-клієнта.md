## А. API сайтів: побажання та A/B-тести

> **26.11: зроблено на сайтах інакше, ніж нижче** (`POST /edits`, `GET /versions`, параметр `?v=`). Платформа підключена: сторінка «Сайти»
> і кнопка «Надіслати на сайт» біля підказок. Лишається бажаним метод читання станів правок. Далі — початкова пропозиція.

Ключ для запису — окремий від нинішнього ключа читання, щоб його можна було відкликати окремо.
Відповіді в тому самому вигляді: `{ "ok": true, "data": … }`.

### А1. Побажання

| Метод | Що робить |
|---|---|
| `POST /wishes` | платформа надсилає побажання. Повтор із тим самим `external_id` оновлює, а не дублює |
| `GET /wishes?site=&status=&after_id=` | список: вам для впровадження, платформі — щоб бачити стан |
| `PATCH /wishes/{id}` | зміна стану: `new → accepted → done` або `rejected` (з причиною) |

```json
{
  "external_id": "ads-2026-11-26-001",
  "site": "auto-lp", "page": "/", "variant": "a",
  "kind": "text",
  "priority": 1,
  "title": "Перший екран не повторює обіцянку реклами",
  "problem": "Кнопку натискають 3 людини з 200",
  "evidence": { "from": "2026-11-24", "to": "2026-11-26", "steps": { "view": 206, "cta_click": 3 } },
  "change": "Заголовок: «Отримайте безкоштовну Карту автоматизації». Одна кнопка в Telegram",
  "how_to_check": "Частка натискань кнопки за наступні 200 відвідувачів"
}
```

`kind`: `text`, `layout`, `speed`, `form`, `tracking`, `ab_test`.
Коли ставите `done`, додавайте `done_at` і, якщо зроблено окремим варіантом, `variant`. Без дати платформа не порівняє «до» і «після».

### А2. A/B-тести

| Метод | Що робить |
|---|---|
| `POST /experiments` | завести тест: сайт, назва, припущення, блок (`data-ab`), варіанти з частками, головний крок, мінімум людей |
| `GET /experiments` | перелік зі станами |
| `PATCH /experiments/{id}` | `running`, `stopped`, переможець |
| `GET /experiments/{id}/results` | люди й кроки по кожному варіанту |

```json
{
  "external_id": "ads-exp-001", "site": "auto-lp", "block": "page",
  "hypothesis": "Сторінка про Карту дає більше переходів у бота, ніж сторінка про консультацію",
  "variants": [ { "v": "a", "weight": 50 }, { "v": "b", "weight": 50 } ],
  "goal_step": "tg_click", "min_visitors_per_variant": 150
}
```

Обовʼязкове:

1. **У кожній події `/events` віддавати `ab`** (наприклад `{"page":"b"}`). Зараз Hub це зберігає, але віддає лише `variant` сторінки.
2. Людина щоразу бачить той самий варіант (за `visitor_id`).
3. `?ab=page:b` у рекламному посиланні примусово показує варіант (вже працює).
4. На одному блоці одночасно один тест.

## Б. Інші дані з сайтів (у порядку користі)

1. **`visitor_id` і `click_id` в усіх подіях**, зокрема в оплатах із сервера (`pay_fail`, `refund`).
2. **Де людина зупинилась:** `scroll_50`, `scroll_90`, `engaged_10s`, `section_view` (назва блока).
3. **Яку саме кнопку натиснули:** поле `meta.button` у `cta_click` і `tg_click`.
4. **Швидкість і поломки:** `meta.load_ms` у `view`; події `js_error`, `form_error` (яке поле).
5. **Чому не пройшла оплата:** `meta.reason` у `pay_fail`.
6. **Журнал змін сторінки:** `GET /changes?site=` (дата, що змінено). Тоді видно, яка правка вплинула на цифри.
7. **Тексти блоків:** `GET /sites/{id}/content`. Платформа пропонуватиме заміну конкретного речення, а не «покращіть перший екран».
8. **Миттєве сповіщення про оплату** (Б6 у контракті): у вас готове й вимкнене, на платформі ще нема приймача.

## В. Воронки (боти)

| № | Пропозиція | Навіщо |
|---|---|---|
| 1 | Етап «Відповів» (перше повідомлення людини). Готовий у гілці іншої сесії, не викладений | видно, чи люди взагалі вступають у розмову; переможця визначає ціна клієнта |
| 2 | Етап на кожен крок: отримав PDF → відповів → «знаю / не знаю» → пропозиція → заперечення → посилання → оплата → запис → консультація | видно, на якому саме повідомленні губимо |
| 3 | Для тих, хто замовк: останній крок, скільки повідомлень написав, через скільки часу відповів вперше. Без імен | зрозуміти причину, а не лише факт |
| 4 | Сума в події «Оплатив» | ціна продажу з бота без ручної позначки |
| 5 | Варіанти текстів: мітка варіанта в посиланні, зберігається в розмові й віддається платформі | A/B у боті без копіювання всієї воронки |
| 6 | Друге нагадування (через 7 днів) зараз не відправляється | повернення тих, хто замовк |
| 7 | Події в Meta з сервера (відповів, запис, оплата) | реклама зможе шукати схожих на тих, хто купує |
| 8 | Після консультації одна кнопка вам у Telegram: «була / не прийшла / купила / відмова і чому» | без цього кінець шляху порожній |

## Г. Сама платформа (роблю я)

1. **Шлях однієї людини** по часу: оголошення → сайт → бот → запис → оплата. Зараз є лише кількості по кроках.
2. **Частка «джерело невідоме»** по кожному кроку з тривогою, коли вона росте.
3. **Тривоги в Telegram із кнопками:** 250 грн витрачено, а бота відкрили менше 5; оголошення відхилене; сторінка не відкривається; оплати падають.
4. **Надсилання побажань на сайти** з кнопки «Аналізувати» (щойно буде А1) і перевірка результату через заданий час.
5. **Позначки змін на цифрах:** коли міняли рекламу, сторінку чи бота.
6. **«Даних досить / ще мало»** біля кожного порівняння варіантів, щоб не обирати переможця навмання.
7. **Пристрій і площадка** в кроках сайту та денна розбивка по площадках (зараз пристрій не зберігається).
8. **Відео:** скільки додивились 3 секунди й половину.
9. **Щоденний розбір за розкладом:** готові побажання й рядки «Історії», ви лише погоджуєте.
10. **Органіка поряд із рекламою:** посилання з Threads із власною міткою, щоб порівнювати з платним.
